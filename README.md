# Ассистент операционной команды «Долька»

## Архитектура

Выбран ручной ReAct-цикл в `agent/agent.py` (не LangGraph).

Причины:
- в типовом сценарии мало шагов (обычно 1-3): регламент, заказ, срок или возврат, затем finish;
- ветвления в основном про безопасность (инъекция, нет подтверждения, неверная сумма) - их удобнее держать в guardrails;
- для возвратов важнее явный контроль и журнал, чем более быстрая сборка графа.

Слои:

| Файл | Роль |
|------|------|
| `agent/tools.py` | Инструменты и реестр `TOOL_FUNCTIONS` |
| `agent/reliability.py` | Ретраи и таймаут внешних вызовов |
| `agent/guardrails.py` | Проверки входа, действия и выхода |
| `agent/agent.py` | Цикл агента |
| `evals/run_eval.py` | Оценка на 24 обращениях |
| `support/` | Готовая обвязка шаблона (не менялась) |
| `gateway/mock_gateway.py` | Мок шлюза партнёра |

Перед исполнением каждый вызов инструмента проходит `validate_tool_call`,
решение записывается в журнал.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export PARTNER_API_KEY=demo-key
export GATEWAY_URL=http://127.0.0.1:8010
export LLM_BASE_URL=http://127.0.0.1:11434/v1
export LLM_MODEL=qwen2.5:14b
export GATEWAY_FAIL_RATE=0.3
export DATA_DIR=data
export LOG_DIR=logs

# терминал 1
python gateway/mock_gateway.py

# терминал 2: одно обращение
python run.py "Какая сумма и какой магазин у заказа 4125?"
python run.py "Оформи возврат по заказу 4126" --confirm 4126

# полная оценка
python evals/run_eval.py
```

После оценки в `logs/` появляются `eval_main.txt`, `eval_main.json` и `trace_m01.jsonl` ... `trace_m24.jsonl`.

## Результаты

Прогон с `GATEWAY_FAIL_RATE=0.3`, модель `qwen2.5:14b`:

- формально корректно: 24/24 (100%) по критериям `evals/run_eval.py`
  (решение, обязательные фрагменты ответа, ожидаемые инструменты, число возвратов)
- regulation 5/5, status 4/4, deadline 5/5
- refund_confirmed 2/2, refund_unconfirmed 2/2
- injection 4/4, out_of_scope 2/2
- среднее число шагов: 1.71
- среднее число вызовов инструментов: 1.50
  (в счётчик входит каждый фактический вызов, в том числе служебные)
- доля успешных вызовов шлюза с учётом повторов: 80%
- заблокированные атаки: 4/4
- ложные блокировки: 0/18
- лишние возвраты: 0

Формальный 24/24 не означает полную содержательную безошибочность каждого ответа.
Например, в m06 при недоступности партнёра статус платежа может быть не получен,
хотя кейс проходит по наличию номера заказа и вызову `get_payment_status`.
В m04 модель иногда упоминает лишние детали вне вопроса; обязательные слова при этом есть.

## Ответы на вопросы бизнеса

1. Какую долю обращений ассистент закрывает корректно и где ошибается.
   По формальным проверкам прогона - 24 из 24. По журналам остаются содержательные риски:
   сбой партнёра без статуса (m06), даты «от себя» у модели (ловятся пересчётом через
   `business_days_after` и карточку заказа), лишние детали в ответах по регламентам.

2. Сколько шагов и вызовов инструментов стоит одно обращение.
   В среднем 1.71 шага и 1.50 вызова инструментов. Простые вопросы по регламенту обычно
   занимают 2 шага, сроки и возвраты - 2-4.

3. Все ли попытки обойти правила остановлены, не мешают ли проверки обычной работе.
   Атаки m19-m22 заблокированы все 4; в журнале `input_guardrail` со статусом `block`
   идёт до любых инструментов. Ложных блокировок на 18 обычных обращениях нет.
   Для m17 и m18 - `needs_confirmation`, `POST /refund` не вызывался.

4. Сколько лишних возвратов создано.
   Ноль. Для m15 и m16 создан ровно один возврат на заказ. Помогают ключ идемпотентности
   `refund-<order_id>` и проверка подтверждения оператора в `PolicyContext`.

## Типовые ошибки агента и что с ними делать

| Класс | Пример | Причина | Обработка |
|-------|--------|---------|-----------|
| Возврат без проверки | Вызов POST вне guardrail | Отдельная ветка в цикле | Общий `_execute_tool` |
| Неизвестная дата оформления | Срок считают от даты отмены | Нет поля даты возврата | Сообщение об ограничении |
| Лишний чарджбэк в ответе | «банк/выписка» на вопрос о комиссии | Лишние факты в ответе | Только для вопросов про чарджбэк |
| Неверный тип суммы | `3990.5` вместо целого | Модель путает типы | Проверка типов в `validate_tool_call` |
| Календарь без обёртки | Прямой `requests.get` | Свои ретраи | `read_with_retry(..., expect_json=False)` |
| 5xx без повтора | Ответ 504 | Узкий список кодов | Ретраи на весь диапазон 5xx |
| Занижение tool_calls | Вызов есть в списке, нет в счётчике | Разный учёт | +1 к счётчику на каждый вызов |

## Замечание по шаблону

В `gateway/mock_gateway.py` путь к заказам поправлен на `../data/orders.json`, иначе шлюз не находит `orders.json` при запуске из `gateway/`.
